# 오답노트

## 문제 1

* **문제명:** 구명보트
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/42885
* **알고리즘 / 자료구조:** 그리디, 정렬, 투 포인터

### 접근 및 시행착오

처음에는 사람들을 두 명씩 묶어서 최대한 많이 태우면 된다고 생각했다.

그런데 그냥 앞에서부터 두 명씩 묶는 방식으로는 최소 개수의 보트를 만들 수 없었다.

그래서 몸무게가 가장 무거운 사람을 기준으로 생각했다.

가장 무거운 사람은 다른 사람과 같이 탈 수 있는 경우가 제한적이기 때문에, 가장 가벼운 사람과 같이 탈 수 있는지를 먼저 확인하면 된다.

가장 무거운 사람과 가장 가벼운 사람의 합이 제한을 넘는다면 다른 사람과는 절대 같이 탈 수 없기 때문에 무조건 혼자 보내야 한다.

### 최종 풀이

먼저 `people`을 오름차순으로 정렬한다.

가장 무거운 사람은 배열의 뒤에서부터 확인하고, 가장 가벼운 사람은 `idx`를 사용해서 앞에서부터 확인했다.

1. 가장 무거운 사람을 확인한다.
2. 가장 가벼운 사람과 같이 탈 수 있는지 확인한다.
3. 두 사람의 몸무게 합이 `limit` 이하라면 두 명을 같이 태우고 `idx`를 증가시킨다.
4. 같이 탈 수 없다면 가장 무거운 사람만 보트에 태운다.
5. 모든 사람을 처리할 때까지 반복한다.

```java
import java.util.*;

class Solution {
    public int solution(int[] people, int limit) {
        int answer = 0;
        Arrays.sort(people);
        
        int idx = 0;
        for(int i=people.length-1; i>=idx; i--){
            if(people[i]+people[idx] <=limit){
                answer++;
                idx++;
            }
            else{
                answer++;
            }
        }
        return answer;
    }
}
```

### 복잡도

* 시간복잡도: `O(N log N)` — 정렬 때문에 발생
* 공간복잡도: `O(1)` — 별도의 배열을 만들지 않고 인덱스만 사용

### 핵심 포인트

가장 무거운 사람부터 처리하는 게 중요하다.

가장 무거운 사람과 가장 가벼운 사람이 같이 탈 수 없다면 다른 사람과도 같이 탈 수 없기 때문에 혼자 보내는 것이 확정된다.

**정렬 + 양쪽에서 접근하는 투 포인터 방식**을 기억해두면 비슷한 문제에서 사용할 수 있을 것 같다.

## 문제 2

* **문제명:** 섬 연결하기
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/42861
* **알고리즘 / 자료구조:** 그리디, 최소 신장 트리(MST), 크루스칼, Union-Find

### 접근 및 시행착오

모든 섬을 연결하면서 비용을 최소로 만들어야 하기 때문에 비용이 작은 다리부터 선택하면 될 것 같다고 생각했다.

하지만 단순히 비용이 작은 다리를 계속 선택하면 이미 연결된 섬을 다시 연결해서 사이클이 생길 수 있다.

그래서 현재 두 섬이 이미 연결되어 있는지를 확인할 방법이 필요했고, `parent` 배열을 이용해서 서로 같은 그룹에 속해 있는지를 확인하도록 했다.

### 최종 풀이

크루스칼 알고리즘을 사용했다.

먼저 다리를 건설하는 비용을 기준으로 오름차순 정렬한다.

그 다음 비용이 작은 다리부터 하나씩 확인하면서 두 섬의 부모를 찾는다.

1. 두 섬의 부모가 같으면 이미 연결되어 있으므로 해당 다리는 선택하지 않는다.
2. 부모가 다르면 아직 연결되지 않은 섬이므로 해당 다리를 선택한다.
3. 두 섬을 같은 그룹으로 만들기 위해 부모를 연결한다.
4. 선택한 다리의 비용을 전체 비용에 더한다.

이 과정을 반복하면 모든 섬을 연결하면서 최소 비용을 구할 수 있다.

```java
import java.util.*;

class Solution {
    static int[] parent;
    
    public int solution(int n, int[][] costs) {
        int answer = 0;
        
        //간선들의 가중치들을 오름차순으로 정렬
        Arrays.sort(costs, (int[] c1, int[] c2) -> c1[2]-c2[2]);
        
        parent = new int[n];
        
        for(int i=0; i<n; i++){
            parent[i] = i;
        }
        
        int total = 0;
        
        for(int[] edge: costs){
            int from = edge[0];
            int to = edge[1];
            int cost = edge[2];
            
            int fromParent = findParent(from);
            int toParent = findParent(to);
            
            if(fromParent == toParent) continue;
            
            total += cost;
            parent[toParent] = fromParent;
        }
        
        return total;
    }
    
    private int findParent(int node){
        if(parent[node] == node) return node;
        return parent[node] = findParent(parent[node]);
    }
}
```

### 복잡도

* 시간복잡도: `O(E log E)` — 다리의 개수를 `E`라고 했을 때 정렬하는 과정
* 공간복잡도: `O(N)` — `parent` 배열

### 핵심 포인트

모든 노드를 최소 비용으로 연결하는 문제는 **최소 신장 트리(MST)**를 생각해볼 수 있다.

크루스칼은 **간선을 비용이 작은 순서대로 정렬한 후 사이클이 생기지 않는 간선만 선택**한다.

그리고 Union-Find를 사용하면 두 노드가 같은 그룹인지 빠르게 확인할 수 있다.

## 문제 3

* **문제명:** 단속카메라
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/42884
* **알고리즘 / 자료구조:** 그리디, 정렬

### 접근 및 시행착오

차량마다 지나가는 구간이 주어지기 때문에 처음에는 각 차량의 구간을 비교하면서 겹치는 위치를 찾아야 한다고 생각했다.

그런데 모든 차량을 하나씩 비교하면 복잡해질 것 같았다.

생각해보니 가장 빨리 고속도로에서 나가는 차량의 진출 지점에 카메라를 설치하면 그 차량을 잡으면서 이후 차량들도 최대한 같이 잡을 수 있었다.

그래서 차량의 **진출 지점 기준으로 정렬**하는 방법으로 풀었다.

### 최종 풀이

먼저 모든 차량을 진출 지점 기준으로 오름차순 정렬한다.

가장 먼저 나가는 차량의 진출 지점에 카메라를 하나 설치한다.

그 다음 차량부터 확인하면서 현재 카메라 위치가 해당 차량의 이동 구간 안에 있는지 확인한다.

* `현재 차량의 진입 지점 <= 카메라 위치`라면 기존 카메라에 걸리기 때문에 추가로 설치할 필요가 없다.
* `현재 차량의 진입 지점 > 카메라 위치`라면 기존 카메라를 지나가지 않기 때문에 새로운 카메라를 설치한다.
* 새로운 카메라는 해당 차량의 진출 지점에 설치한다.

이렇게 하면 필요한 카메라 수를 최소화할 수 있다.

```java
import java.util.*;

class Solution {
    public int solution(int[][] routes) {
        int answer = 1;
        
        // -15 -13 -5 -3
        Arrays.sort(routes, (o1, o2) -> o1[1]-o2[1]);
        
        int location = routes[0][1]; //카메라설치
        
        for(int i=1; i<routes.length; i++){
            if(routes[i][0] > location){
                answer++;
                location = routes[i][1];
            }
        }
        
        return answer;
    }
}
```

### 복잡도

* 시간복잡도: `O(N log N)` — 진출 지점 기준으로 정렬
* 공간복잡도: `O(1)` — 별도의 자료구조를 사용하지 않음

### 핵심 포인트

구간 문제에서 **끝나는 지점이 빠른 것부터 정렬**하는 방식이 자주 사용될 수 있다는 것을 알게 됐다.

현재 카메라 위치가 다음 차량의 구간 안에 있으면 그대로 사용하고, 구간을 벗어나면 새로운 카메라를 설치하면 된다.

특히 그리디 문제에서는 무조건 작은 값을 고르는 게 아니라 **현재 선택이 이후에도 최대한 많은 경우를 처리할 수 있는지** 생각하는 게 중요한 것 같다.
