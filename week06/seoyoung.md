## 문제 1

### 문제 정보

* 문제명: 피로도
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/87946
* 사용한 알고리즘 / 자료구조: 완전탐색, 백트래킹, 순열, 방문 배열

### 처음 접근 방식

던전마다 필요한 피로도와 소모 피로도가 있으니, 어떤 순서로 탐험해야 가장 많이 갈 수 있는지 모든 경우를 확인해야 한다고 생각했다.

### 풀이 방법

1. 각 던전을 방문했는지 확인할 방문 배열을 만든다.
2. 현재 피로도와 탐험한 던전 수를 DFS 함수에 넘긴다.
3. 아직 방문하지 않은 던전 중 현재 피로도가 최소 필요 피로도 이상인 던전을 고른다.
4. 해당 던전을 방문 처리하고, 피로도를 소모한 상태로 다음 DFS를 호출한다.
5. 탐색이 끝나면 방문 처리를 다시 해제해서 다른 순서도 확인한다.
6. 탐험한 던전 수의 최댓값을 계속 갱신한다.

### 어려웠던 지점

소모 피로도가 적은 던전부터 가거나, 최소 필요 피로도가 높은 던전부터 가는 식의 정렬만으로는 항상 정답이 나오지 않았다.

던전 개수가 최대 8개라서 모든 순서를 확인해도 된다는 제한 조건을 먼저 보는 것이 중요했다.

### 해결 방법

한 가지 기준으로 정렬하지 않고, 방문 가능한 던전을 하나씩 선택하면서 모든 순서를 백트래킹으로 탐색했다.

방문 처리와 해제를 정확히 해주면 같은 던전을 중복으로 가지 않으면서도 다른 순서를 모두 확인할 수 있다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N!)
* 공간복잡도: O(N)

던전의 가능한 방문 순서를 탐색하므로 최악의 경우 순열의 개수만큼 확인한다.

### 새롭게 알게 된 점

입력 크기가 작을 때는 그리디를 억지로 찾기보다, 가능한 경우를 전부 확인하는 완전탐색이 더 단순하고 정확할 수 있다.

## 문제 2

### 문제 정보

* 문제명: 메뉴 리뉴얼
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/72411
* 사용한 알고리즘 / 자료구조: 조합, 완전탐색, HashMap, 정렬

### 처음 접근 방식

각 손님이 주문한 메뉴에서 코스 길이에 맞는 조합을 모두 만들고, 가장 많이 나온 조합을 고르면 된다고 생각했다.

### 풀이 방법

1. 각 주문 문자열의 문자를 오름차순으로 정렬한다.
2. course에 있는 길이마다 주문 문자열에서 가능한 조합을 만든다.
3. 만든 조합을 HashMap에 저장하면서 등장 횟수를 센다.
4. 같은 길이의 조합 중 등장 횟수가 가장 큰 값을 찾는다.
5. 등장 횟수가 2 이상이고 최댓값과 같은 조합만 정답에 추가한다.
6. 최종 정답 배열을 사전순으로 정렬해서 반환한다.

### 어려웠던 지점

같은 메뉴 조합이라도 주문 문자열의 순서가 다르면 다른 문자열처럼 처리될 수 있었다.

예를 들어 `AC`와 `CA`가 같은 조합이 되도록, 조합을 만들기 전에 메뉴를 정렬해야 했다.

### 해결 방법

각 주문을 먼저 정렬한 뒤 조합을 만들었다.

또 코스 길이별로 따로 횟수를 세고 최댓값을 구해서, 길이가 다른 조합끼리 비교하지 않도록 했다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(M * C)
* 공간복잡도: O(C)

`M`은 주문 수이고, `C`는 각 주문에서 만들 수 있는 조합의 총 개수이다.

### 새롭게 알게 된 점

조합 문제에서는 같은 원소 묶음을 같은 형태로 저장하는 것이 중요하다. 문자열을 정렬해서 기준을 맞추면 HashMap으로 개수를 세기 쉬워진다.

## 문제 3

### 문제 정보

* 문제명: 후보키
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42890
* 사용한 알고리즘 / 자료구조: 부분집합, 조합, 브루트포스, Set, 비트마스킹

### 처음 접근 방식

컬럼의 개수가 최대 8개라서, 가능한 컬럼 조합을 모두 확인하면서 후보키가 되는지 검사하면 된다고 생각했다.

### 풀이 방법

1. 컬럼 인덱스의 모든 부분집합을 만든다.
2. 이미 찾은 후보키를 포함하는 조합이면 최소성을 만족하지 않으므로 건너뛴다.
3. 현재 컬럼 조합으로 각 행의 값을 하나의 문자열로 합친다.
4. 합친 값을 Set에 넣어서 모든 행이 서로 구분되는지 확인한다.
5. Set의 크기가 행의 수와 같으면 유일성을 만족한다.
6. 유일성과 최소성을 모두 만족하는 조합을 후보키 목록에 추가한다.
7. 최종 후보키 개수를 반환한다.

### 어려웠던 지점

유일성만 만족한다고 바로 후보키가 되는 것이 아니었다.

이미 더 작은 컬럼 조합으로 식별이 가능하다면, 거기에 컬럼을 더 붙인 조합은 최소성을 만족하지 못한다.

### 해결 방법

부분집합을 검사할 때 이미 찾은 후보키가 현재 조합에 포함되어 있는지 먼저 확인했다.

비트마스크를 사용하면 포함 관계를 `AND` 연산으로 간단하게 판단할 수 있었다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(2^C * R * C)
* 공간복잡도: O(2^C + R)

`C`는 컬럼 수, `R`은 행 수이다. 가능한 컬럼 부분집합을 모두 확인하고, 각 조합마다 모든 행을 검사한다.

### 새롭게 알게 된 점

부분집합을 모두 탐색하는 문제에서는 조건 검사의 순서가 중요하다. 후보키 문제는 최소성을 먼저 확인하면 불필요한 유일성 검사를 줄일 수 있다.
